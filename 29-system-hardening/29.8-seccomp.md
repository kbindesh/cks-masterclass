# Restrict system calls using seccomp

## `System Calls` Basics

### What is a `System Call`?

- A `System call` is a procedure that provides the interface between a process and the operating system.

- A `System Call` is a programmatic way for a user application to ask the Linux kernel to perform tasks that require higher privileges, like:
  - accessing files
  - managing processes
  - using network sockets
- In Linux, we have over 400 syscalls and all of them can be used by apps running in the user-space to carryout hardware and networking tasks.

- System calls are categorized into 5 types:
  1. **Process Control**
     - fork()
     - exit()
     - exec()
     - wait()
     - kill()
  2. **File Management**
     - open()
     - read()
     - write()
     - close()
  3. **Device Management**
     - ioctl()
  4. **Information Maintenance**
     - getpid()
     - alarm()
     - sleep()
  5. **Communication** (IPC/Networking)
     - pipe()
     - shmget() - Shared memory segment
     - mmap -

- Because, user applications cannot access hardware or kernel space directly due to security and stability reasons, _System calls_ are used to access these features safely.

## Restricting syscalls

- **Why to restrict the systemcalls?**
  - By default, the linux kernel will allow any syscall to be invoked by programs running inside the user-space.
  - This increases the attack surface for the malicious users.
  - That is where we can use `seccomp (secure computing)`
