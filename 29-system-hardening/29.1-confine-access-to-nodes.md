# Confine access to K8s Nodes

# Recommended Practices for restricting access to K8s Nodes

- On self-hosted kubernetes cluster, as a recommended practice, we should limit exposure of the _Control plane_ and _Worker nodes_ to the Internet.

- In order to access the private k8s nodes securely, you may setup VPN solution.
- You may also whitelist authorized networks (range of IPs) in the organization's firewall; works at Layer-3.
- Allow SSH access to Nodes only to the users who actually need it (e.g. Cluster Administrators and not to a Tester/End users)

## Linux Systems Users types

- Linux systems primarily categorize users into following types:
  1. **Root User (Superuser)**
     - It has unlimited access and full control over the entire system, including all files, commands, and administrative tasks
     - It is identified by a User ID (UID) of **0**.
     - Home directory is typically `/root`

  2. **Regular Users**
     - User accounts created for general, everyday use by human operators.
     - They have limited permissions, primarily confined to their own home directories and specific resources they have been granted access to.
     - Regular users typically have UIDs of 1000 or greater.

  3. **System Users**
     - **Service Accounts**
       - These are non-interactive accounts created by the installed services or applications to run background processes or daemons securely.
       - e.g. www-data for a web server, mysql for a database server, or postfix for a mail server.
       - They usually have UIDs below 1000 and generally do not have a login shell or a home directory

     - **System Accounts**
       - These are non-interactive accounts created by the OS to run background processes or daemons securely.
       - e.g. ssh, mail
       - They usually have UIDs below 1000 and generally do not have a login shell or a home directory

## Linux useful commands

```
# Get UID, GID and Group membership info about any user
id $USERNAME

# To display information about current logged-in Users
who

# To display a history of user logins and logouts
last
last -n 5
last username
last reboot

# Disable a User account by updating the default shell to nologin
usermod -s /bin/login $USERNAME

# To check the user's default shell
grep -i $USERNAME /etc/passwd

# To Delete a user completely from the system
userdel $USERNAME

# Add a User to a group
usermod -aG $GROUP_NAME $USERNAME
usermod -aG docker ec2-user

# Remove a User from a Group
deluser $USERNAME $GROUP_NAME
deluser bindesh admin
OR
gpasswd -d $USERNAME $GROUP_NAME
gpasswd -d bindesh admin
```

## Linux systems - Useful files

```
# To get the basic info about all the Users
```
