# Service Mesh and `Istio`

## 01. Service Mesh Overview

- Service Mesh provides traffic management, observability, reliability and security for microservices.

## 02. Istio Overview

- Istio is an open-source service mesh that provides a transparent way to connect, secure, and monitor microservices.
- It works primarily with Kubernetes, extending its capabilities to handle complex networking tasks without requiring changes to your application's code.

- Key Capabilities
  - Traffic Management
  - Security
  - Observability
  - Resiliency

### 2.1 Istio Architecture

- Istio is logically divided into two main planes:
  1. `Data Plane`
     - Composed of a set of intelligent proxies (typically Envoy) that are deployed alongside your applications.
     - These proxies mediate and control all network communication between microservices.
  2. `Control Plane`
     - Managed by a component called Istiod, which provides service discovery, configuration, and certificate management.
     - It converts your high-level routing rules into proxy-specific configurations.

### 2.2 Istio Deployment Modes

- **Sidecar Mode**
  - The traditional method where an _Envoy proxy_ runs in every pod alongside the application container.

- **Ambient Mode**
  - A newer, sidecar-less architecture that uses a shared node-level proxy (ztunnel) for Layer 4 security and optional "Waypoints" for Layer 7 features, simplifying operations and reducing overhead.

## 03. Lab: Install and Configure `Istio` on K8s

### 3.1 System Requirements

- Kubernetes cluster with atleast 4GB memory

### 3.2 Install Istio using Helm

- Install Helm

```bash

# Install Helm
sudo dnf install -y git

curl -fsSL -o get_helm.sh https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-4

chmod 700 get_helm.sh

./get_helm.sh
```

- Now, let's install Istio CRDs in sidecar mode using Helm:

```bash

helm repo add istio https://istio-release.storage.googleapis.com/charts


helm repo update

# Search for Istio named packages on repository
helm search repo Istio

# Install Istio CRD's (istio/base chart to setup Istio in sidecar mode)
helm install istio-base istio/base -n istio-system --set defaultRevision=default --create-namespace

# List the Istio CRDs
kubectl get crds

[It contains CRDs realted to security, traffic management, telemetry, extensions and workloads]
```

- Install Istio Daemon (Istiod)

```bash
# Install Istio Daemon (Istiod)
helm install istiod istio/istiod -n istio-system --wait

# Verifying Istio installation
kubectl -n istio-system get po,deploy,svc
```

### 3.3 Install `istioctl`

- `Istioctl` is a command-line tool to access and manage the Istio Daemon from the local machine.

```bash
curl -sL https://istio.io/downloadIstioctl | sh -
export PATH=$HOME/.istioctl/bin:$PATH
echo 'export PATH=$HOME/.istioctl/bin:$PATH' >> ~/.bashrc
source ~/.bashrc

# Check istioctl version
istioctl version
```

### 3.4 Enable Istio Sidecar injection

```bash

# Deploy Sidecars Automatically To A Namespace e.g. here in default ns
kubectl label namespace default istio-injection=enabled --overwrite
```

### 3.5 Deploy an Application to test the Istio sidecar containers

```bash
kubectl run --image=nginx nginx
kubectl get pods -o yaml

[observe istio-init and istio-proxy containers]
```

## 04. Lab: Install and Configure `Kiali` on K8s

- Kiali is an observability console for Istio with service mesh configuration and validation capabilities.
- It helps you understand the structure and health of your service mesh by monitoring traffic flow to infer the topology and report errors.

### 4.1 Prerequisites

- K8s cluster
- istio (kiali requires istio)
- kubectl

### 4.2 Install `Kiali`

```bash
kubectl apply -f https://raw.githubusercontent.com/istio/istio/release-1.29/samples/addons/kiali.yaml

# Verify installation
kubectl rollout status deployment/kiali -n istio-system

# (optional, only for minikube cluster)
# Publish or Expose Kiali on Host (port-forwarding)
kubectl port-forward svc/kiali 20001:20001 -n istio-system
```

### 4.3 Access the Kiali Dashboard

- Open your browser and navigate to: `https://$HOST_IP_OR_DNS_NAME:20001`

## 05. Secure Apps communication using `Istio` and `mTLS`

- Istio provides mutual TLS (mTLS) to secure service-to-service communication in K8s by:
  - `Automating encryption`
    - Istio transparently upgrades traffic between services in the mesh to mTLS.
    - Proxies (Envoy sidecars or Ambient ztunnels) handle encryption and decryption, requiring no changes to application code.

  - `Identity verification`
    - Istiod acts as the Certificate Authority (CA) and assigns each service a unique cryptographic identity (SPIFFE ID) derived from its K8s Service Account.
  - `Certificate management`
    - Istio automatically generates, distributes, and rotates X.509 certificates.
    - Workload certificates are typically short-lived (e.g., 24 hours) to limit exposure if compromised

### 5.1 mTLS Enforcement Modes

- You can configure [_PeerAuthentication_](https://istio.io/latest/docs/reference/config/security/peer_authentication/) resources at the _mesh_, _namespace_, or _workload_ level to control mTLS enforcement.

| Name       | Description                                                            |
| ---------- | ---------------------------------------------------------------------- |
| UNSET      | Inherit from parent, if has one. Otherwise treated as&nbsp;PERMISSIVE. |
| DISABLE    | Connection is not tunneled.                                            |
| PERMISSIVE | Connection can be either plaintext or mTLS tunnel.                     |
| STRICT     | Connection is an mTLS tunnel (TLS with client cert must be presented). |

## 06. Lab: Enable `mTLS` in `STRICT` mode

- Policy to require mTLS traffic for all workloads under default namespace.

```bash
apiVersion: security.istio.io/v1
kind: PeerAuthentication
metadata:
  name: default
  namespace: default
spec:
  mtls:
    mode: STRICT
```
