# Cilium

## Cilium Overview

- Cilium is an open-source, CNCF-graduated project providing high-performance networking, security, and observability for cloud-native environments, specifically Kubernetes.

- Layer 3/4 and Layer 7 network policies
- Transparent encryption for pod-to-pod communication
- Cilium leverages `eBPF (extended Berkeley Packet Filter)` technology to enable:
  - efficient, kernel-level packet processing
  - replacing traditional iptables for faster networking
  - load balancing, and
  - identity-aware security policies

### Key Features of Cilium

- eBPF-Powered CNI
  - Acts as a Container Network Interface (CNI) plugin, offering superior performance, lower latency, and reduced CPU usage by bypassing inefficient parts of the Linux networking stack.
- Security & Policy Enforcement
  - Implements identity-based (rather than just IP-based) network policies, allowing fine-grained control at Layer 3, 4, and 7 (HTTP/gRPC).
- Observability (Hubble)
  - Provides deep visibility into network flows, DNS queries, and application-level events, helping troubleshoot connectivity issues.
- Service Mesh & Networking
  - Supports advanced networking features including BGP, IPv6, service mesh capabilities, encryption (IPSec/WireGuard), and Egress Gateways.
- Cluster Mesh
  - Enables connectivity and security policies across multiple Kubernetes clusters.

### Cilium - Common Use Cases

- Kubernetes Networking
  - Providing fast, scalable CNI networking for Pods

- Financial services applications handling sensitive data
- Network Security
  - Implementing Zero Trust security policies
- Replacing Kube-proxy
  - Using eBPF for efficient service load balancing
- Observability
  - Using Hubble to map service dependencies and network traffic
- Healthcare systems with patient information
- Compliance-driven environments (PCI DSS, HIPAA, SOC 2)

## Install and Configure Cilium on K8s (minikube)

- You must start the cluster with the default CNI disabled so that Cilium can take over.

```bash
minikube start --network-plugin=cni --cni=false

# Install the Cilium CLI
CILIUM_CLI_VERSION=$(curl -s https://raw.githubusercontent.com/cilium/cilium-cli/master/stable.txt)

# Download the Cilium binary
curl -L --fail --remote-name-all https://github.com/cilium/cilium-cli/releases/download/${CILIUM_CLI_VERSION}/cilium-linux-amd64.tar.gz

# Extract the downloaded Cilium binary and move it to /usr/local/bin
sudo tar xzvfC cilium-linux-amd64.tar.gz /usr/local/bin

rm cilium-linux-amd64.tar.gz

# Install Cilium
cilium install

# Verify the Cilium installation
cilium status --wait
cilium connectivity test
```

## Pod-to-Pod Encryption with Cilium

### Why there is a need of Pod-to-Pod Encryption?

- Security Benefits
  - Zero Trust Architecture
  - Compliance Requirements
  - Defense in Depth
  - Multi-tenancy

### Cilium Encryption Methods

- Cilium provides multiple methods for transparent encryption to secure data in transit within a Kubernetes cluster without requiring application-level changes.

#### 1. IPsec (Internet Protocol Security)

- `IPsec` is a mature, industry-standard protocol for authenticating and encrypting network packets.

- Mechanism: Uses the Linux kernel's built-in xfrm framework.

- Key Management: Requires manual creation of a Kubernetes Secret containing a Pre-Shared Key (PSK).
- Use Cases: Ideal for environments requiring FIPS compliance or integration with existing IPsec infrastructure.
- Limitations: Encryption and decryption are typically limited to a single CPU core per tunnel, which may impact high-throughput performance.

#### 2. WireGuard

- WireGuard is a modern, high-performance encryption protocol known for its simplicity and efficiency.

- Mechanism: Creates a secure peer-to-peer tunnel between nodes using the cilium_wg0 interface.
- Key Management: Automates key pair generation and rotation; public keys are distributed via Kubernetes annotations.
- Performance: Generally more efficient than IPsec with lower CPU overhead
