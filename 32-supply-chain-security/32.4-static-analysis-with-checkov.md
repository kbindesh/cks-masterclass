# Static Analysis using `checkov`

## `checkov` Overview

- Checkov is a static code analysis tool for infrastructure as code (IaC) and also a software composition analysis (SCA) tool for images and open source packages.

- It scans cloud infrastructure provisioned using:
  - Terraform, Terraform plan
  - Cloudformation
  - AWS SAM
  - Kubernetes
  - Helm charts
  - Kustomize
  - Dockerfile
  - Bicep
  - OpenAPI
  - ARM Templates
- Checkov detects security and compliance misconfigurations using graph-based scanning.

## Install and Configure `Checkov`

```bash

# Install Python
sudo dnf install python3

# Install pip
sudo dnf install -y python3-pip
OR
sudo apt update && sudo apt install python3-pip

# Create and activate a virtual environment
python3 -m venv checkov-env
source checkov-env/bin/activate

# Install Checkov
pip install checkov

# Confirm the installation by checking the version
checkov --version
```

## Checkov - Basic Usage

- Once installed, you can immediately start scanning your Infrastructure as Code (IaC) files:

```bash
# Scan a directory
checkov -d /path/to/code

# Scan a specific file
checkov -f example.tf
checkov -f file.yaml

# Scan specific framework
checkov -d . --framework kubernetes

```

## Lab: Static Analysis using `checkov`

- Scanning a Kubernetes manifest with `Checkov` is a quick way to catch security misconfigurations before they ever hit your cluster, like:
  - running as root
  - missing CPU limits

### Develop a K8s manifest (say, for deployment)

- This manifest intentionally violates several security best practices.

```bash
apiVersion: apps/v1
kind: Deployment
metadata:
  name: insecure-nginx
spec:
  replicas: 1
  template:
    spec:
      containers:
      - name: nginx
        image: nginx:latest # Violated: Lacks specific version, securityContext, and resource limits
```

- Running `checkov -f deployment.yaml` against this manifest will trigger multiple failures, such as missing resource limits and running as root.

- Now, you can go ahead and fix the highlighted issues by checkov. The updated manifest will look something like this:

```bash
apiVersion: apps/v1
kind: Deployment
metadata:
  name: secure-nginx
spec:
  template:
    spec:
      securityContext:
        runAsNonRoot: true
      containers:
      - name: nginx
        image: nginx:1.25.0
        securityContext:
          allowPrivilegeEscalation: false
        resources:
          limits:
            cpu: "500m"
```
